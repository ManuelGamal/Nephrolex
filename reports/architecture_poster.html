Architecture

fan-out at build time, fan-in at query time

Read A left to right, B left to right, C right to left. The vertical drops are the only cross-lane links: indexes are built once and sit directly above the retrievers that consult them, and fusion hands its ranking straight down to the reranker. Amber marks the document-expansion path — generated text reaches ranking and the cross-encoder, and stops there. It never reaches a citation.

Safety appears twice because it runs twice. A paediatric dosing question is stopped before retrieval — it never reaches an index, a model, or an API bill. A question built on a threshold that does not exist can only be caught once evidence is in hand. Splitting the gate is why the system records zero unsafe answers and zero false declines rather than trading one against the other. The dashed red path is the other half of that argument: an LLM phrasing that fails verification is discarded, and the verbatim extractive answer stands.

The evaluation chain

six links, each fails differently
01 Is the corpus faithful to the PDF? check_corpus.py 169/169 labelled items
02 Is the right chunk retrieved? evaluate_gold.py nDCG@10 0.7074
03 Is it the right row of the table? check_table_rows.py 18/19 = 95%
04 Does the citation resolve to real text? check_citations.py 99.1%
05 Does the answer state the right value? check_answers.py 74.8%
06 Can a fabricated value get through? check_generation.py 0 of 22

Link 05 is the one usually missing. Retrieval metrics say the chunk was found and citation checks say the citation is real, but neither asks whether the number a clinician reads is correct. Its own known flaw is reported with it: 1 expectation in 107 is a reference number that the extractor reads as a range.

Measured and kept

the one technique that cleared its confidence interval

doc2query in clinician voice

clinician-phrased +0.1612 · CI [+0.075, +0.258]

A clinician asks about “a flozin” and the word appears in neither guideline. An LLM writes, per chunk, the questions a clinician would actually ask — 4,208 of them, generated once and cached — indexed separately, so generated text can move ranking and can never reach a citation, a quote or the verifier.

The phrasing gap it closes

0.9423 echo · 0.7818 clinician-phrased

Same content, same answer key, differing only in wording. Retrieval quality on this system depends heavily on whether a question uses guideline vocabulary, which is invisible to any benchmark written by reading the corpus.

Tuned, then re-measured

every constant swept against the pipeline that exists now

· Candidates each retriever nominates 120 / 240 → 120 doubling gains nothing
· Candidates the cross-encoder scores 20 / 30 / 50 50 loses a question

All three had been inherited from a pipeline that no longer exists. All three came back at the value already running — a duller result than a gain, and a more useful one. Depth 50 scoring worse than 30 is the instructive case: a wider window admits competitors the cross-encoder prefers over the right answer.

Built, measured, deleted

a negative result with a mechanism beats an untested assumption
· Contextual Retrieval every chunk given a situating sentence −0.0964 paraphrase
· MedCPT encoder trained on 255M PubMed click logs −0.267 echo
· HyDE query rewriting search on a hypothetical answer CI spans zero
· ColBERT late interaction 176k token vectors, MaxSim −0.0053 fused
· Vector database Qdrant, fully ingested 17.0 ms vs 0.4 ms flat
· BM25 kept for recall, on an assumption recall@20 +0.0074 without

Six techniques built and removed, one kept. MedCPT is the one worth reading twice: it halved the phrasing gap — by dragging the strong side down, not lifting the weak one. Reporting the gap alone would have called it a success.
